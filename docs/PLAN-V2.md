## 2. איפה אנחנו היום (הבסיס)

- הטלויזיה (`/`) היא מקור האמת, מריצה `setInterval` ומחזיקה את כל ה-state.
- הנייד (`/remote`) הוא שלט דק: מחזיק טיוטה, שולח `cmd`/`apply`, מקבל `tick`.
- אין התחברות. כל הגישה ל-Supabase היא ב-anon key, טבלאות עם policy "allow all".
- **`/icon.png` לא קיים בריפו** — כלומר שני המניפסטים מצביעים על אייקון חסר וההתקנה
  כ-PWA שבורה כבר עכשיו. זה תוקן בשלב 4.

## 3. ההחלטה הארכיטקטונית המרכזית: שעון עוגן

השאלה הקשה ביותר בהיפוך היא **מי מריץ את השעון**. אם נעביר את ה-`setInterval`
לנייד, נשבור את כל האימון ברגע שהמסך ננעל — iOS מקפיא JS בטאב רקע. ואם נשאיר
אותו בטלויזיה, הנייד לא באמת שולט.

**הפתרון: אף אחד לא סופר שניות ברשת. שני הצדדים מחשבים מעוגן.**

```js
// מצב האימון שהנייד מפרסם
{
  cursor: { drillIdx, phaseIdx },
  clock:  { running, phaseStartedAt, remainingAtPause, phaseDuration },
  drills: [...]
}

// שני הצדדים גוזרים אותו דבר
timeLeft = running
  ? phaseDuration - (now - phaseStartedAt) / 1000
  : remainingAtPause
```

מה זה קונה:

- **אין דריפט.** אין הצטברות שגיאה כמו ב-`setInterval` — כל טיק מחושב מחדש מהעוגן.
- **הטלויזיה שורדת נייד ישן.** מסך ננעל, אפליקציה ברקע, רשת נופלת — הטלויזיה
  ממשיכה לספור נכון בלי לקבל אף הודעה.
- **חיבור מחדש מרפא מיידית.** הודעת עוגן אחת והכול מסונכרן.
- **פחות תעבורה.** במקום `tick` כל שנייה — הודעה רק כשמשהו באמת משתנה.

### מי מחליט על מעבר שלב

פונקציה טהורה משותפת `app/lib/sessionEngine.js`:
`phasesOf(drill)`, `nextCursor(drills, cursor, globalAutoNext)`, `deriveClock(anchor, now)`.

- הנייד מחליט ומפרסם עוגן חדש — הוא הסמכות.
- הטלויזיה, אם הגיעה ל-0 ולא שמעה עוגן חדש תוך ~1.2 שניות, **מתקדמת לבד**
  באותה פונקציה. כי היא טהורה, שני הצדדים מגיעים לאותה תוצאה. עוגן מהנייד תמיד
  גובר. ככה ההקרנה לא נתקעת אף פעם, גם אם הנייד ישן.

### הפרש שעונים בין המכשירים

שעון הנייד ושעון הטלויזיה יכולים להיות רחוקים בשניות. מוסיפים לפרוטוקול
`ping/pong` עם חותמות זמן, כל צד מעריך `offset` (חציון של כמה דגימות), ומחיל
אותו על העוגן שמגיע. בלי זה השעון על המסך יכול לקפוץ.

### צליל

נשאר **בטלויזיה** — היא הרמקול באולם. היא סופרת את שלוש הביפים האחרונים
מהשעון הגזור שלה, לא מהודעת רשת, כדי שהצליל יהיה מדויק גם ברשת גרועה.
הבאנר "🔊 לחצו כאן להפעלת הצלילים" נשאר — מגבלת AudioContext לא השתנתה.

| טאב | תוכן |
|---|---|
| 🎛 ניהול אימון | שעון, ▶/⏸, ± זמן, ניווט תרגילים ושלבים, עריכת המערך תוך כדי, זוגות, הערות |
| 📺 הקרנה | **מראה חיה של הטלויזיה** + מתג "עכשיו / אחרי העדכון" + ✓ עדכן טלויזיה + מצב החיבור |

מעל שני הטאבים רצועה דקה קבועה (תרגיל נוכחי · זמן · ▶/⏸), כדי ששליטה תהיה
תמיד במרחק נגיעה אחת — גם כשמסתכלים על ההקרנה.

### רנדרר אחד לשני המקומות

מוציאים מ-`JudoTrainer.jsx` קומפוננטה טהורה `<ProjectionScreen state scale />`.

- `/tv` מרנדר אותה במסך מלא.
- טאב ההקרנה בנייד מרנדר את **אותה קומפוננטה** בתוך קופסת 16:9 עם `transform: scale()`.

זה מה שנותן WYSIWYG אמיתי בחינם, ומונע שתי מימושי UI שמתפצלים עם הזמן.
ו"אחרי העדכון" הוא פשוט אותה קומפוננטה עם `merge(live, draft)` במקום `live`.

## 6. נתונים, מועדונים והרשאות

סכימה חדשה. תרוץ ידנית ב-SQL Editor של Supabase — **Supabase חסום מסביבת ה-agent**,
אז אני מייצר את הקובץ ואתה מריץ אותו.

```sql
clubs     (id, name, slug, owner_id, created_at)
profiles  (id → auth.users, display_name, club_id, role)          -- coach | admin
groups    (id, club_id, name, color)
athletes  (id, club_id, group_id, name, belt, side, personal_drills jsonb)
drills    (id, owner_id, club_id, name, section, type, spec jsonb,
           visibility default 'shared', forked_from, tags text[], uses)
plans     (id, owner_id, club_id, group_id, name, drills jsonb,
           visibility default 'shared')                            -- מערכי אימון
club_invites (code, club_id, created_by, expires_at, used_by)       -- צירוף מאמן
sessions  (id, club_id, group_id, plan_id, coach_id, started_at, ended_at,
           drills jsonb, present_ids jsonb, notes, stats jsonb)     -- היסטוריה
```

**גבול הקטלוג — הוחלט: המועדון.** "משותף" פירושו גלוי למאמני אותו מועדון,
לא לכל הפלטפורמה. לכן גם התווית בממשק לא תהיה "ציבורי" אלא **👥 משותף למועדון**,
כדי שהמתג יגיד את האמת. ברירת המחדל היא משותף, והמתג הוא 🔒 **פרטי**.

**RLS:**
```sql
-- drills / plans — קריאה
club_id = my_club() AND (visibility = 'shared' OR owner_id = auth.uid())
-- drills / plans — כתיבה ומחיקה
owner_id = auth.uid()
```
- כל השאר — מוגבל ל-`club_id = my_club()`.
- פונקציית עזר `my_club()` שקוראת מ-`profiles`.
- הערך בעמודה נקרא `'shared'` ולא `'public'`, כדי שהסכימה לא תשקר לגבי ההיקף.
  אם בעתיד נרצה קטלוג חוצה־מועדונים, זה ערך שלישי (`'public'`) ולא שינוי משמעות.

**עריכת תרגיל של מאמן אחר = פיצול (fork).** נוצר עותק עם `owner_id = אני`
ו-`forked_from = המקור`. אף פעם לא משנים שורה של מאמן אחר — רלוונטי כפליים
עכשיו, כשכמה מאמנים חולקים מועדון ורואים אחד את התרגילים של השני.

**מועדון = כמה מאמנים.** `profiles.club_id` משייך מאמן למועדון, וכל הקבוצות,
הספורטאים והמערכים משותפים לכל מאמני המועדון. צריך גם מסלול הצטרפות: המאמן
הראשון יוצר מועדון והופך ל-`admin`, ומזמין מאמנים נוספים בקוד הזמנה
(`club_invites`, קוד קצר עם תפוגה) — בלי זה אין דרך למאמן שני להיכנס למועדון.

**התחברות: אימייל + סיסמה.** Supabase Auth. `app/lib/auth.js` חדש; `supa()`
מתרחב לשלוח את ה-JWT של המשתמש במקום ה-anon key, עם רענון שקט. `/` מציג מסך
התחברות בלי session; `/tv` לא דורש התחברות בכלל.
אין תלות בהגעת מייל ברגע האמת — מה שחשוב באולם עם קליטה גרועה. איפוס סיסמה
כן ישתמש במייל, אבל זה מסלול נדיר ולא חוסם כניסה לאימון.

**הגירה:** `drill_library → drills`, `workouts → plans`, `attendance → sessions`,
הכול משויך למועדון "BGU" ולמשתמש שלך. סקריפט אידמפוטנטי, אפשר להריץ פעמיים.

## 7. להפוך את זה ל-PWA אמיתי

- **אייקונים** — `icon-192`, `icon-512`, `icon-maskable-512`, `apple-touch-icon`.
  (היום חסר לגמרי, ולכן ההתקנה שבורה.)
- **service worker** — precache לקליפת האפליקציה, network-first עם נפילה ל-cache
  עבור Supabase REST, ואף פעם לא caching ל-WebSocket.
- **התקנה** — כפתור "הוסף למסך הבית" על `beforeinstallprompt`, והוראות ידניות
  ל-iOS (שם אין אירוע כזה).
- **אופליין** — המערך האחרון, הקבוצות והקטלוג נשמרים ב-IndexedDB, כתיבות נכנסות
  לתור ונשלחות כשהרשת חוזרת. אימון שלם אפשרי בלי קליטה.

## 10. מה שהוכרע

| שאלה | ההחלטה | מה זה גורר |
|---|---|---|
| התחברות | אימייל + סיסמה | בלי תלות בהגעת מייל בזמן אימון |

נותר פתוח, ולא חוסם: האם למאמן זמני (מחליף) צריך תפקיד נפרד מ-`coach`.
