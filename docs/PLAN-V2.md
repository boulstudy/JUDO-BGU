# תוכנית V2 — מאפליקציית טלויזיה עם שלט, לאפליקציית מאמן עם הקרנה

מסמך העבודה למימוש. מתאר **מה משתנה, למה, באיזה סדר, ואיך יודעים שזה עובד**.

> הנחיה שקיבלתי: לעשות גם את מה שלא התבקש אבל חייב להיות. סעיף 8 הוא כל מה
> שנוסף מהשיקול הזה, עם נימוק לכל פריט — כדי שתוכל לפסול פריטים שאתה לא רוצה.

---

## 1. ארבע הבקשות

| # | הבקשה | מה זה אומר טכנית |
|---|---|---|
| 1 | PWA אמיתי בנייד | service worker, אייקונים, התקנה למסך הבית, ריצה בלי רשת |
| 2 | השליטה מהנייד; הטלויזיה מצטרפת בקוד | **היפוך תפקידים** — הנייד מקור האמת, הטלויזיה מקרן |
| 3 | ריבוי מועדונים ומאמנים; קטלוג משותף | Auth + RLS + סכימה חדשה + ברירת מחדל משותפת |
| 4 | ניווט מלא + "התחל אימון" + שני טאבים | קליפה עם **שני מצבים**: מצב בית ומצב אימון |

## 2. עקרונות שמנחים את כל ההחלטות למטה

1. **האימון לא נעצר.** כל תקלה — רשת, סוללה, מסך ננעל, דפדפן קרס — חייבת
   להשאיר את הטלויזיה סופרת נכון. זה הקריטריון שגובר על כל שיקול אחר.
2. **שקיפות במקום קסם.** מה שנשמר — נאמר. מה שנכשל — נאמר. היום `supa()` מחזיר
   `null` בשקט וכל הקוראים מתעלמים; במוצר לכמה מאמנים זה אובדן נתונים שקט.
3. **הפרדה בין מועדונים היא לא פיצ׳ר, היא חוזה.** רשימת ספורטאים היא מידע אישי,
   לעיתים של קטינים. דליפה בין מועדונים היא כשל הכי חמור במערכת.
4. **היסטוריה לא משתנה למפרע.** עריכת מערך היום לא מרשה לשנות מה קרה בשבוע שעבר.

## 3. הלב: שעון עוגן

השאלה הקשה בהיפוך היא **מי מריץ את השעון**. `setInterval` בנייד נשבר ברגע
שהמסך ננעל — iOS מקפיא JS בטאב רקע. שעון בטלויזיה מרוקן את ההיפוך ממשמעות.

**הפתרון: אף אחד לא סופר שניות ברשת. שני הצדדים גוזרים מעוגן.**

```js
// מה שהנייד מפרסם
{ cursor: { drillIdx, phaseIdx },
  clock:  { running, phaseStartedAt, remainingAtPause, phaseDuration } }

// מה ששניהם מחשבים מקומית, כל frame
timeLeft = running
  ? phaseDuration - (now - phaseStartedAt) / 1000
  : remainingAtPause
```

| מה זה קונה | למה |
|---|---|
| אין דריפט | כל טיק מחושב מהעוגן, במקום לצבור שגיאה |
| שורד נייד ישן | הטלויזיה ממשיכה נכון בלי לקבל אף הודעה |
| ריפוי מיידי | חיבור מחדש = הודעת עוגן אחת |
| פחות תעבורה | הודעה רק בשינוי, לא `tick` כל שנייה |

### מי מחליט על מעבר שלב
פונקציה טהורה משותפת `app/lib/sessionEngine.js` —
`phasesOf(drill)`, `nextCursor(drills, cursor, autoNext)`, `deriveClock(anchor, now)`.

הנייד מחליט ומפרסם. אם הטלויזיה הגיעה ל-0 ולא שמעה עוגן תוך 1.2 שניות, היא
מתקדמת לבד באותה פונקציה — טהורה, ולכן שניהם מגיעים לאותה תוצאה. עוגן מהנייד
תמיד גובר. ההקרנה לא נתקעת גם אם הנייד ישן.

### הפרש שעונים
`ping/pong` עם חותמות זמן; כל צד מעריך `offset` כחציון של 5 דגימות ומחיל אותו
על העוגן הנכנס. בלי זה השעון על המסך קופץ בשניות.

### צליל
נשאר בטלויזיה — היא הרמקול באולם. סופרת את שלוש הביפים מהשעון הגזור שלה ולא
מהודעת רשת. הבאנר לפתיחת AudioContext נשאר; מגבלת הדפדפן לא השתנתה.
בנוסף הנייד ירטוט (`navigator.vibrate`) במעבר שלב — למאמן שלא מסתכל למסך.

## 4. אבטחת ההקרנה — לא התבקש, חייב

היום קוד של 4 תווים פותח ערוץ broadcast ציבורי, וכל מי שמצטרף לערוץ יכול גם
**לשלוח פקודות**. בפרויקט של קבוצה אחת זה לא מעניין. במוצר לכמה מועדונים, זר
שמנחש topic יכול להשתלט על הקרנה באמצע אימון, או להאזין לה.

| מה | איך |
|---|---|
| קוד ארוך יותר | 6 תווים מאלפבית של 32 ⇒ ‎1e9‎ צירופים במקום ‎1e6 |
| בעלות על החיבור | הנייד מגריל `sessionKey`; הטלויזיה נועלת את המפתח הראשון שראתה ומתעלמת מכל השאר — כמו הצמדה, אמון בפעם הראשונה |
| החלפת שלט מכוונת | "השתלטות" מפורשת בטלויזיה בלחיצה, לא בשקט |
| הגנה מהודעה חוזרת | `seq` עולה מונוטונית; הודעה ישנה נזרקת |
| תפוגה | הקוד מתחלף בסוף אימון ואחרי חוסר פעילות |

הערוץ נשאר אפמרי, בלי טבלה חדשה. `sessionKey` לא מוצג למשתמש ולא נשמר בשרת.

## 5. מסכים ונתיבים

```
/        אפליקציית המאמן   PWA · portrait · standalone   ← הבית החדש
/tv      מקלט ההקרנה       PWA · landscape · fullscreen · בלי התחברות
/remote  הפניה ל-/         כדי ש-PWA מותקן קיים לא יישבר
```

הטלויזיה **לא מתחברת לחשבון** — מסך באולם לא מחזיק סיסמת מאמן. הקוד הוא
ההרשאה היחידה שלה, ולכן סעיף 4.

### מצב בית
| טאב | תוכן |
|---|---|
| 🏠 היום | הקבוצה של היום, האימון המוצע, כפתור **התחל אימון** |
| 📋 מערכי אימון | שלי / המועדון, עורך מערך |
| 👥 קבוצות | קבוצות, ספורטאים, זוגות, נוכחות |
| 📚 קטלוג | חיפוש תרגילים, סינון לפי מקטע, "שלי" |
| ⋯ עוד | היסטוריה, הגדרות, חשבון, חיבור להקרנה |

### מצב אימון — בדיוק שניים, כמו שביקשת
| טאב | תוכן |
|---|---|
| 🎛 ניהול אימון | שעון, ▶/⏸, ± זמן, ניווט תרגילים ושלבים, עריכת המערך חי, זוגות, הערות |
| 📺 הקרנה | מראה חיה של הטלויזיה + מתג **עכשיו / אחרי העדכון** + ✓ עדכן טלויזיה + מצב חיבור |

מעל שניהם רצועה דקה קבועה (תרגיל · זמן · ▶⏸), כדי ששליטה תהיה במרחק נגיעה גם
כשמסתכלים על ההקרנה.

### רנדרר אחד
מחלצים מ-`JudoTrainer.jsx` קומפוננטה טהורה `<ProjectionScreen state scale />`.
`/tv` מרנדר אותה במסך מלא; טאב ההקרנה מרנדר את **אותה** קומפוננטה בקופסת 16:9
עם `transform: scale()`. WYSIWYG בחינם, ואין שני מימושי UI שמתפצלים.
"אחרי העדכון" = אותה קומפוננטה עם `merge(live, draft)`.

## 6. נתונים והרשאות

```sql
clubs        (id, name, slug, owner_id, created_at)
profiles     (id → auth.users, display_name, club_id, role, created_at)
club_invites (code, club_id, created_by, expires_at, used_by, used_at)
groups       (id, club_id, name, color, archived_at)
athletes     (id, club_id, group_id, name, belt, side, personal_drills jsonb, archived_at)
drills       (id, owner_id, club_id, name, section, type, spec jsonb,
              visibility default 'shared', forked_from, tags text[], uses, archived_at)
plans        (id, owner_id, club_id, group_id, name, drills jsonb,
              visibility default 'shared', archived_at)
sessions     (id, club_id, group_id, plan_id, coach_id, started_at, ended_at,
              local_date, drills jsonb, present_ids jsonb, notes, stats jsonb)
```

**גבול הקטלוג הוא המועדון.** "משותף" = גלוי למאמני אותו מועדון, לא לפלטפורמה.
לכן התווית בממשק היא **👥 משותף למועדון** ולא "ציבורי" — מתג צריך להגיד את
האמת — והערך בעמודה הוא `'shared'`. אם בעתיד תרצה קטלוג חוצה-מועדוני, זה ערך
שלישי (`'public'`) ולא שינוי משמעות של נתונים קיימים.

```sql
-- drills / plans — קריאה
club_id = my_club() AND (visibility = 'shared' OR owner_id = auth.uid())
-- drills / plans — כתיבה ומחיקה
owner_id = auth.uid()
-- כל השאר
club_id = my_club()
```

- **עריכת תרגיל של מאמן אחר = פיצול.** עותק עם `forked_from`. אף פעם לא משנים
  שורה של מאמן אחר — קריטי כפליים כשמאמנים חולקים מועדון ורואים זה את תרגילי זה.
- **צירוף מאמן.** הראשון יוצר מועדון והופך `admin`, ומזמין בקוד עם תפוגה.
  בלי זה אין דרך למאמן שני להיכנס — לכן `club_invites` נוסף אף שלא התבקש.
- **התחברות: אימייל + סיסמה.** בלי תלות בהגעת מייל ברגע האמת. איפוס סיסמה
  משתמש במייל, אבל זה מסלול נדיר שלא חוסם כניסה לאימון.

## 7. PWA

- **אייקונים** — `192`, `512`, `maskable`, `apple-touch-icon`. היום
  `/icon.png` **לא קיים בריפו** ושני המניפסטים מצביעים עליו, כלומר ההתקנה שבורה
  כבר עכשיו. נייצר אותם בסקריפט שמשתמש רק ב-`node:zlib`, בלי תלות חדשה
  (Vercel מתקין devDependencies, ולכן לא מוסיפים ספריית תמונות).
- **service worker** — precache לקליפה, network-first עם נפילה ל-cache ל-REST,
  ואף פעם לא caching ל-WebSocket.
- **התקנה** — כפתור על `beforeinstallprompt`, והוראות ידניות ל-iOS.
- **אופליין** — מערך, קבוצות וקטלוג ב-IndexedDB; כתיבות בתור. אימון שלם בלי קליטה.

## 8. מה שלא ביקשת ובכל זאת נכנס

כל פריט עם הנימוק שלו, כדי שתוכל לפסול.

### 8.1 אמינות באולם
| מה | למה בלי זה נשבר |
|---|---|
| **נעילת מסך בנייד לאורך אימון** | הנייד עכשיו מקור האמת. מסך שנכבה = מאמן שמגשש בכיס באמצע ראנדורי. `useWakeLock` קיים; מרחיבים אותו לתפוס מחדש אחרי חזרה מרקע |
| **שחזור אימון פעיל** | הסוללה נגמרת באמצע. מצב האימון נשמר ב-`localStorage` ובשורת `sessions`; פתיחה מחדש שואלת "יש אימון פעיל — להמשיך?" והטלויזיה בינתיים המשיכה מהעוגן |
| **שלט אחד בכל רגע** | שני מאמנים שפותחים את אותו אימון ידרסו זה את זה. סעיף 4 נותן את המנגנון; ה-UI מראה "שלט אחר מחובר — להשתלט?" |
| **תור כתיבות אופליין** | אולם עם קליטה גרועה. שמירה נכשלת ⇒ נכנסת לתור ונשלחת כשחוזרת רשת |
| **הודעות שגיאה אמיתיות** | היום `supa()` מחזיר `null` בשקט. מחזירים `{data, error}` + טוסט. אחרת מאמן חושב ששמר ולא שמר |
| **טיוטה נשמרת מקומית** | רענון דף באמצע עריכת מערך לא יאבד עבודה |

### 8.2 שלמות נתונים
| מה | למה |
|---|---|
| **מחיקה רכה (`archived_at`)** | `sessions.plan_id` מצביע על מערך. מחיקה קשה תשמיד היסטוריה |
| **האימון מצלם את המערך בהתחלה** | `sessions.drills` הוא עותק. עריכת המערך מחר לא תשנה מה קרה אתמול |
| **תאריך מקומי, לא UTC** | היום `new Date().toISOString().slice(0,10)`. בישראל זה נכון לאימוני ערב ונשבר רק אחרי חצות מקומית — אבל מרגע שיש מועדונים באזורי זמן אחרים זה מתייק כל אימון ערב ליום הלא נכון. נשמר `local_date` מפורש |
| **גיבוי לפני הגירה** | `pg_dump`/יצוא CSV של שלוש הטבלאות הקיימות לפני שמריצים משהו |
| **סדר פריסה** | הסכימה עולה **לפני** הקוד, והקוד החדש יודע לקרוא גם את הישן לתקופת מעבר. הפוך = אתר שבור |

### 8.3 חוויה שאי אפשר בלעדיה בנייד
| מה | למה |
|---|---|
| **`env(safe-area-inset-bottom)`** | טאבים תחתונים באייפון יושבים מתחת לפס הבית בלי זה |
| **יעד מגע 44px, כפתורים בחצי התחתון** | מפעילים את זה ביד אחת, בעמידה, באולם |
| **מצבי ריק + קטלוג התחלתי** | מאמן חדש נכנס לחשבון ריק ולא יודע מה לעשות. נזרע קטלוג פתיחה מהתרגילים הקיימים |
| **מסלול הצטרפות** | יצירת מועדון → הזמנת מאמן → קבוצה ראשונה → מערך ראשון |
| **שיוך זוגות אוטומטי** | הזוגות היום ידניים ומקובעים. כפתור "שבץ זוגות" לפי נוכחות ומשקל/רמה חוסך למאמן חמש דקות בתחילת כל אימון |

### 8.4 תפעול
| מה | למה |
|---|---|
| **CI ב-GitHub Actions** | אין היום. חמישה PR-ים ברצף בלי build+בדיקות אוטומטיות זה איך שנשבר main |
| **מתג חירום ל-service worker** | SW תקול נועל משתמשים על גרסה שבורה. נתיב `/sw-kill` שמבטל רישום ומנקה cache |
| **גרסת פרוטוקול בהודעה** | נייד מעודכן מול טלויזיה ישנה יציג "רענן את הטלויזיה" במקום להתנהג מוזר |
| **מפתחות Supabase ל-env** | `NEXT_PUBLIC_SUPABASE_URL/ANON_KEY` במקום קבוע בקוד. ה-anon key נועד להיות ציבורי, אבל מה שמגן עליו זה RLS — שהיום הוא "allow all" |
| **בדיקת בידוד מועדונים** | בדיקה אוטומטית שמועדון א׳ לא קורא נתוני מועדון ב׳. סעיף 2.3 |

## 10. בדיקות

- **יחידה** — `sessionEngine` טהור ⇒ בדיקות מהירות בלי דפדפן: דריפט, קפיצת שעון,
  עריכה תוך כדי ריצה, `nextCursor` בקצוות.
