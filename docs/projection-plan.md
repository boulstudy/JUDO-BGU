# תוכנית: הקרנה, חיבור ותצוגה נגישה

**סטטוס: יושם** (שלבים 0–5 + QR), ראו CLAUDE.md ← "מצב נוכחי". המסמך נשאר כתיעוד ההחלטות והנימוקים. נכתב מעל `main` אחרי PR #8.

## עקרונות

1. **שני תרחישים, שתי זרימות** — אין "מצב אחד שמתאים לכולם":
   - **מכשיר יחיד (שיקוף):** הנייד *הוא* המסך. השעון רץ בנייד, השליטה במגע.
   - **שני מכשירים (טלויזיה חכמה / מחשב):** המסך מריץ את השעון, הנייד שלט.
2. **אותה תצוגה בדיוק בשני התרחישים** — רכיב אחד (`StageView`) שמצויר ביחידות
   יחסיות למסך, כך שהוא נראה זהה על טלויזיה 4K ועל נייד משוקף.
3. **הקלדה רק בנייד.** הטלויזיה מציגה, הנייד מקליד/סורק.
4. **כל מידע מוצג בשני ערוצים** — צבע + טקסט, צליל + אות חזותי.

## שלב 0 — פירוק (בלי שינוי התנהגות)

`JudoTV` (≈600 שורות) מערבב היום מנוע שעון, תצוגה, כלי עריכה וחיבור. כדי
שהתצוגה והשעון ירוצו גם בנייד, מפרקים:

| חדש | תוכן | מקור |
|---|---|---|
| `app/lib/clock.js` → `useWorkoutClock({drills, globalAutoNext, sound})` | `drillIdx/phaseIdx/timeLeft/running/totalElapsed/alertActive`, `advancePhase`, האינטרוול עם `tickCtxRef`, אפקט האיפוס לפי `drillClockSignature`, `clockOverrideRef`/`applyClock`, `goToDrill`, `nextPhaseManual`, `addTime`, `startPlaying`, וגם `personalTimers` | `JudoTrainer.jsx` 590–735 |
| `app/lib/stage.jsx` → `StageView` + `SplitPanel` | כל מה שהמתאמנים רואים: שם תרגיל, שעון, שלב, מי עובד, הבא, התקדמות, רשימת מערך, דגשים. **בלי כפתורים.** | `JudoTrainer.jsx` 372–430, 924–1120 |

`JudoTV` נשאר עם: מודאלים, סרגל כלים, חיבור לשלט — ומרכיב `useWorkoutClock` + `StageView`.

**סיכון:** מלכודת #1 ו-#2 ב-CLAUDE.md. הסדר בין אפקט האיפוס לאפקט ה-override
חייב להישמר בתוך ה-hook. **רשת ביטחון:** 37 הבדיקות הקיימות (במיוחד `e2e-clock.js`)
חייבות לעבור בלי שינוי לפני שממשיכים.

## שלב 1 — תצוגה נגישה לאולם (`StageView`)

### מה המתאמן צריך לקרוא מ-5–10 מטר, לפי סדר חשיבות
1. **כמה זמן נשאר** — השעון.
2. **מה עושים עכשיו** — שם התרגיל + השלב (עבודה / מנוחה / החלפה).
3. **מי עובד** — לבן / כחול / שניהם.
4. **מה הבא.**
5. הקשר: התקדמות, רשימת מערך, דגשים.

### כללים
| נושא | היום | בתוכנית |
|---|---|---|
| **גודל** | px קבועים + זום ידני (`scale`) | הכול ב-`vmin`/`vh`: שעון ≈ 32vh, שם תרגיל ≈ 7vh, תווית שלב ≈ 5vh, "הבא" ≈ 4vh, רשימה ≈ 3vh. הזום נשאר רק ככיול עדין |
| **ניגודיות** | טקסטים ב-`rgba(255,255,255,0.17–0.3)`, 10–13px | מינימום 4.5:1 לכל טקסט שמתאמן אמור לקרוא (בערך ≥ 0.7 אטימות על הרקע הכהה). דקורציה בלבד יכולה להישאר עמומה |
| **שלב** | עבודה `#00ff88` ומנוחה `#a8ff78` — שני ירוקים כמעט זהים | **רצועת שלב** עם טקסט גדול + צבע מובחן: עבודה = ירוק, מנוחה = כחול-תכלת, החלפה = כתום. לעולם לא צבע לבד |
| **מי עובד** | אימוג׳י 🥋 (תמיד לבן) + הכרטיס הלא-פעיל ב-30% אטימות + "עובד" ב-10px | **כחול / לבן** עם אייקון SVG של ג׳ודוגי (קימונו + חגורה) בצבע הצד — `app/lib/GiIcon.jsx`, צבע כפרמטר. הפעיל מלא עם "עובד ✓" גדול; הלא-פעיל מסומן "מנוחה" בטקסט, לא רק מעומעם |
| **3 שניות אחרונות** | צפצוף בלבד | ספרות 3·2·1 ענקיות על המסך — באולם רועש לא תמיד שומעים |
| **החלפה** | מסגרת אדומה מהבהבת ב-0.35ש׳ (≈3 הבהובים לשנייה — גבול סף WCAG להתקפים) | הבזק אחד של רקע + טקסט "החלפה!" למשך 2 שניות, פעימה של 1Hz לכל היותר, ו-`prefers-reduced-motion` מבטל אנימציות |
| **ספרות** | `letterSpacing:-8` (ספרות נדבקות במרחק) | `font-variant-numeric: tabular-nums`, ריווח רגיל — השעון לא "רוקד" ונקרא ממרחק |
| **מנוחה** | "מנוחה" קטן מתחת לשעון | מסך מנוחה: "מתכוננים ל־" + שם התרגיל הבא בגדול |
| **הערות** | `textarea` עריך על המסך המוקרן | "דגשים" לקריאה בלבד, מוצג רק אם יש תוכן. עורכים מהנייד/העורך |
| **רשימת מערך** | כל התרגילים ב-13px | עכשיו + 3 הבאים, גדול. הרשימה המלאה רק כשהשעון עצור |

### "מסך נקי" (היום: "מצב הקרנה")
- שינוי שם בכל המקומות (`JudoTrainer.jsx`, `PATCH_LABELS` ב-`RemoteControl.jsx`).
  שם השדה בפרוטוקול (`projection`) נשאר — אין צורך לשבור תאימות.
- **אוטומטי כשהשלט מחובר:** אם `remoteConnected` — הכפתורים בטלויזיה מוסתרים
  ממילא, כי שולטים מהנייד. נגיעה/מקש על הטלויזיה מחזירה אותם ל-5 שניות.

### מקלדת / שלט טלויזיה / קליקר (טלויזיה ומחשב, בלי נייד)
- `Space`/`Enter` = התחל/עצור, `←`/`→` ו-`PageUp`/`PageDown` (קליקר מצגות) = תרגיל
  הבא/קודם, `↑`/`↓` = ±10 שניות, `F` = מסך מלא.
- טבעת פוקוס כתומה ועבה על כל כפתור — בדפדפן טלויזיה מנווטים בחצים.

## שלב 2 — מצב מכשיר יחיד: `/solo`

נתיב חדש `app/solo/page.js` + `app/solo/SoloScreen.jsx` + `public/solo-manifest.json`
(`start_url:/solo`, `fullscreen`, `landscape`).

### מה רץ
- `useWorkoutClock` + `StageView` + `useSound` + `useWakeLock` — אותו מנוע ואותה
  תצוגה כמו בטלויזיה. **אין** `useTvLink`, אין Supabase Realtime.
- טעינת מערך: האימון האחרון מ-Supabase (כמו היום) + טיוטה מקומית
  (`localStorage.judo_solo_draft`) כדי שעריכה לפני אימון לא תיאבד.
- צליל: המאמן נוגע בנייד, אז ה-AudioContext נפתח לבד; בשיקוף הצליל עובר לטלויזיה.

### שליטה במגע (הכול נראה גם בטלויזיה — מעוצב כך שלא יפריע)
| מחווה | פעולה |
|---|---|
| נגיעה בכל מקום | מציגה פס שליטה תחתון ל-4 שניות (נשאר פתוח כשהשעון עצור) |
| החלקה ← / → | תרגיל הבא / קודם (עם טוסט "▶ תרגיל הבא: X" כדי שיהיה ברור מה קרה) |
| בפס: ⏸/▶ ענק, ⏭ שלב, ±30ש׳, ✏️ עריכה, ⚙️ | כפתורים ≥ 64px, ניגודיות מלאה |

נגיעה **לא** עוצרת את השעון ישירות — מניעת עצירה בטעות כשהנייד ביד.

### עזרי שיקוף
- **כיוון אורך:** שכבה "סובבו את הנייד לרוחב 🔄" (שיקוף לאורך = פס צר בטלויזיה).
  באנדרואיד גם `screen.orientation.lock("landscape")` אחרי מסך מלא.
- **מסך מלא:** `requestFullscreen` בנגיעה הראשונה (אנדרואיד). באייפון זה לא קיים
  לדפי אינטרנט → כרטיס הדרכה חד-פעמי "הוסיפו למסך הבית" (המניפסט פותח ב-fullscreen).
- **כרטיס פתיחה חד-פעמי:** "1. הפעילו *נא לא להפריע* — התראות יופיעו בטלויזיה.
  2. שיקוף מסך: אייפון — מרכז הבקרה ← שיקוף מסך; אנדרואיד — Smart View / Cast."
### עריכה פרטית בשיקוף (החלטה: העריכה לא נראית במסך המשוקף)
מגבלה טכנית: בשיקוף, הטלויזיה מציגה בדיוק את מה שעל מסך הנייד — אין דרך מדפדפן
להראות למאמן משהו שלא יופיע בטלויזיה. לכן:

- **טיוטה + סנכרון** (כמו ב-`/remote`): `✏️ עריכה` פותח את העורך על **עותק** של המערך.
  `StageView` ממשיך לצייר את המצב המוצג; השינויים נכנסים רק בלחיצה על
  "**🔄 סנכרן לשיקוף**" (או "בטל"). אותו מנגנון `pickPatch` / patch דליל.
- **פרטיות בזמן העריכה:** לחיצה על `✏️ עריכה` פותחת קודם מסך ביניים
  "העריכה תופיע בטלויזיה — עצרו את השיקוף" עם הוראה קצרה לפי מכשיר
  (אייפון: מרכז הבקרה ← שיקוף מסך ← הפסק). כפתור "עצרתי, פתח עריכה" + "ערוך בכל זאת".
  אחרי "סנכרן" — "אפשר לחדש את השיקוף".
- **פעולות מהירות** (⏸/▶, ±זמן, דילוג) לא עוברות דרך טיוטה — הן ממילא מיועדות לכולם.
- **ההמלצה לטווח הארוך:** סטרימר זול (Chromecast with Google TV / Fire TV Stick)
  או מחשב ישן ב-HDMI הופכים טלויזיה "טיפשה" לחכמה → מצב שני מכשירים, שבו העריכה
  פרטית לגמרי בלי לעצור שום שיקוף.

## שלב 3 — חיבור: הטלויזיה מציגה, הנייד סורק

### הטלויזיה (`/display`)
- אם אין `localStorage.judo_room` → מייצרת קוד (`makeRoomCode(4)`) ושומרת. **הקוד קבוע
  לאותו מסך** עד ש"קוד חדש".
- **מסך פתיחה** כשאין שלט מחובר והשעון לא רץ: הקוד בספרות ענק + "פתחו בנייד
  judo-bgu.vercel.app ← הנייד שלי ← הקלידו את הקוד" (+ QR בשלב 3ב).
  גלוי לכולם עד שהשלט מתחבר — מקובל כרגע, ייתכן שיוסתר בהמשך. כפתור "המשך בלי שלט" (פוקוס ראשוני — נוח לשלט טלויזיה).
  ברגע שמתחבר שלט → "✓ שלט מחובר" ל-1.5ש׳ והמסך נסגר.
- אחרי החיבור הקוד לא מוצג; זמין דרך "📱 שלט" (כמו היום).
- טוסט "📱 שלט התחבר" בכל חיבור חדש — שקיפות למה שקורה.
- "קוד חדש" → קוד חדש, כל השלטים הישנים מנותקים (הם פשוט בחדר ישן).

### ה-QR — שלב 3ב, אופציונלי
לא חובה: הקוד בן 4 תווים ונשמר בנייד אחרי החיבור הראשון, כך שמקלידים אותו
פעם אחת. ה-QR חוסך את ההקלדה ואת פתיחת הכתובת — נוחות, לא תנאי.
- `app/lib/qr.js` — מקודד QR ב-JS טהור (byte mode, ECC M, גרסאות 1–6), פלט SVG.
  ~200 שורות, בלי תלות ובלי שירות חיצוני.
- תוכן: `${location.origin}/remote?code=ABCD` (≈45 תווים → גרסה 4).
- **לא צריך סורק באפליקציה** — מצלמת המערכת באייפון/אנדרואיד מזהה QR ופותחת
  את הקישור. `/remote` כבר קורא `?code=` היום (`RemoteControl.jsx:132`).

### הנייד (`/remote`)
- **מפסיק לייצר קוד.** סדר: `?code=` → `judo_remote_room` שמור → מסך "התחברות":
  - "📷 סרקו את הקוד שעל המסך" (הסבר: פותחים מצלמה ומכוונים)
  - שדה הקלדה של 4 תווים (`inputMode` מתאים, אותיות גדולות אוטומטית)
  - "אין טלויזיה חכמה? 🪞 שקף את הנייד" → `/solo`
- אחרי חיבור — שומר את הקוד; באימון הבא מתחבר לבד.
- סטטוס חיבור **בטקסט** ("מחובר למסך" / "מחפש מסך…") ולא רק נקודה צבעונית.

### אימות
נוכחות פיזית: רק מי שרואה את המסך יכול לסרוק. הקוד מוצג רק לפני שמתחברים,
יש טוסט על כל חיבור, ו"קוד חדש" מנתק הכול. לנבחרת זה מספיק — בלי חשבונות.

### פרוטוקול
אין שינוי בהודעות. `remoteBus.js` ו-`remoteProtocol.js` נשארים.

## שלב 4 — מסך כניסה (`/`)

```
        🥋 נבחרת ג׳ודו BGU
        מה המכשיר הזה?

  ┌──────────────────────┐  ┌──────────────────────┐
  │ 📺 המסך באולם          │  │ 📱 הנייד שלי           │
  │ טלויזיה חכמה / מחשב    │  │                      │
  └──────────────────────┘  └──────────────────────┘
                                   │
                    ┌──────────────┴───────────────┐
            🔗 יש מסך עם האתר פתוח        🪞 אשקף את הנייד לטלויזיה
                → /remote                       → /solo
```

- **זיהוי אוטומטי:** UA של טלויזיה (`Tizen|Web0S|webOS|SMART-TV|BRAVIA|AFT|Android TV|CrKey|HbbTV`)
  → "המסך באולם" מסומן ומקבל פוקוס. לא מפנים אוטומטית — רק ממליצים.
- **זיכרון:** הבחירה האחרונה נשמרת ומוצגת ראשונה ("בפעם הקודמת: …").
- כפתורים ענקיים, פוקוס גלוי, עובד בחצים.
- `public/home-manifest.json` ייעודי (`standalone`, בלי כיוון כפוי) — סוגר את
  הנקודה הפתוחה ב-CLAUDE.md.

## שלב 5 — נגישות בשלט בנייד (`/remote`)

- כפתור ▶/⏸ באזור האגודל (תחתון), ≥ 64px. כל יעד מגע ≥ 48px.
- `aria-label` לכל כפתור אייקון (🎛 ⚙️ ⏭ וכו'), `aria-live` לסטטוס החיבור ולשעון המשוקף (מנומס, פעם בשלב).
- `navigator.vibrate(30)` על פקודה מיידית (אנדרואיד) — אישור בלי להסתכל.
- ניגודיות: אותו כלל 4.5:1 כמו ב-`StageView`.
