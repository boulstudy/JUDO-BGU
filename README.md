# JUDO-BGU — מנהל אימוני ג׳ודו

אפליקציית מאמן בנייד + מקלט הקרנה לטלויזיה. הנייד הוא מקור האמת; הטלויזיה
מקרינה. `CLAUDE.md` הוא מסמך העבודה המלא — מבנה קבצים, החלטות, מלכודות, ומצב
מדויק של כל שלב. **זה הקובץ לפתוח קודם בסשן חדש.** המסמך הזה הוא סקירה כללית
בלבד + איפה בדיוק עצרנו עכשיו.

**מה קרה אחרי שה-PR נפתח:**
1. CI נכשל בריצה הראשונה — לא קשור לקוד: `actions/setup-node@v4` עם
   `cache: npm` דורש lockfile, ו-`package-lock.json` מוחרג ב-`.gitignore`
   בכוונה (מוסכמה קיימת בפרויקט). תוקן בקומיט נפרד (הסרת `cache: npm`),
   ואומת מקומית לפני הדחיפה. CI ירוק מאז.
2. **תעלומה שלא נפתרה:** תגובת Vercel על ה-PR הראתה בשלב מסוים שכתובת
   הפרודקשן `judo-bgu.vercel.app` עצמה (לא כתובת preview של הענף) מצביעה
   על ה-build של הענף — **בעוד שה-PR עדיין לא מוזג**. זה קורה בדרך כלל רק
   אם מישהו לוחץ "Promote to Production" ידנית ב-Vercel. **שאלתי את המשתמש
   על כך ולא קיבלתי עדיין תשובה.** צריך לברר: האם זה קרה בכוונה? אם כן —
   ה-production כבר מריץ קוד v2 (בטוח, כי `NEXT_PUBLIC_ENABLE_CLUBS` כבוי —
   ר׳ למטה), אבל `main` ב-git עדיין מצביע על הקוד הישן, כלומר git
   ו-production לא מסונכרנים. שווה לוודא עם המשתמש ואולי למזג את ה-PR
   כדי שהמצב יתאזן.

**מה עדיין פתוח על ה-PR:**
- לוודא עם המשתמש את סעיף 2 למעלה.
- לשאול אם למזג את ה-PR ל-`main` (טרם קיבלתי אישור מפורש למיזוג עצמו,
  רק לפתיחתו).
- להמשיך לעקוב אחרי CI/הערות ביקורת עד שה-PR ייסגר, לפי ה-check-in
  שמתוזמן (ר׳ Routines / `send_later`).

**מה המשתמש צריך לעשות (ללא תלות בי, בפרויקט Supabase האמיתי):**
1. `supabase/backup.sql` → `supabase/schema.sql` → `supabase/migrate.sql`
   (אחרי עריכת `target_owner` בתוך הקובץ) — ב-SQL Editor של הפרויקט.
   בפעם הקודמת שניסה, `migrate.sql` נכשל כי `target_owner` לא נערך —
   זו הגנה מכוונת בקוד, לא תקלה.
2. רק אחרי שה-SQL רץ בהצלחה: להוסיף `NEXT_PUBLIC_ENABLE_CLUBS=1`
   ב-Vercel → Environment Variables.

עד אז, ובלי קשר למיזוג ה-PR — **האתר החי ממשיך לעבוד בדיוק כמו היום**
(local-first, בלי מסך התחברות), כי הדגל כבוי כברירת מחדל בכוונה.

## מה זה

מנהל אימוני ג׳ודו. Next.js 14 (app router) + React 18, בלי ספריות UI, כל
הסגנון inline. Supabase לאחסון (REST גולמי, בלי `@supabase/supabase-js`)
ולערוץ realtime בין הנייד לטלויזיה.

- אתר: `judo-bgu.vercel.app`
- GitHub: `boulstudy/JUDO-BGU`
- Supabase: `oakbpcjxjunppuyddpsj.supabase.co`

## ארכיטקטורה (v2)

| מסך | נתיב | תפקיד |
|---|---|---|
| אפליקציית מאמן | `/` | **מקור האמת** — מחזיקה עוגן שעון, מריצה בקרה, שני מצבים |
| הקרנה | `/tv` | מקלט טיפש — מצטרף בקוד (או מייצר אחד), גוזר שעון מהעוגן |
| — | `/remote` | הפניה בלבד ל-`/`, לא לשבור PWA מותקן ישן |

`/` עצמה: **מצב בית** (היום / מערכים / קבוצות / קטלוג / עוד) לפני שמתחילים
אימון, ו**מצב אימון** (בדיוק שני טאבים: ניהול אימון / הקרנה) אחרי לחיצה על
"התחל אימון".

**הרעיון המרכזי — שעון עוגן:** אף צד לא סופר שניות ברשת. הנייד מפרסם "כך
וכך נשאר, ברגע הזה", ושני הצדדים גוזרים ממנו זמן באותה פונקציה טהורה
(`app/lib/sessionEngine.js`). נייד שנועל מסך / יורד מרשת / קורס — ההקרנה
ממשיכה לספור נכון, כי היא אף פעם לא ספרה בעצמה.

פירוט מלא של כל שלב (0–4 + התיקון האחרון), כל מה שנבדק ואיך, וכל מלכודת
שנפלנו בה — ב-**`CLAUDE.md`**. תוכנית הבנייה המקורית — ב-`docs/PLAN-V2.md`.

## מבנה קבצים בקצרה

```
app/
  page.js, layout.js         אפליקציית המאמן ("/") — קליפה, PWA meta
  coach/                     CoachApp, ManageTab, ProjectionTab, HomeTabs...
  tv/                        ProjectionReceiver — מקלט ההקרנה ("/tv")
  sw-kill/                   איפוס חירום — service worker + caches
  lib/                       sessionEngine (★ המנוע הטהור), ProjectionScreen,
                              sessionLink/projectionLink, auth, clubData,
                              store, mobileUI, supabase...
legacy/v1/                   הטלויזיה/שלט הישנים — לעיון בלבד, לא נבנה
supabase/                    schema.sql, migrate.sql, backup.sql
test/                        unit + e2e — ר׳ CLAUDE.md להרצה
docs/PLAN-V2.md              תוכנית הארכיטקטורה המקורית
CLAUDE.md                    ★ מסמך העבודה המלא — לקרוא קודם
```
